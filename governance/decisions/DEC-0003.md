# DEC-0003 · No reorganizar físicamente el código (app/, scripts/, data/)

**Fecha:** 2026-07-27 · **Responsable:** Director técnico (ratificado por asesores) · **Estado:** vigente

## Contexto
Se propuso mover `app/`, `scripts/` y `data/` dentro de una carpeta `runtime/` para que la estructura física reflejara las 4 capas conceptuales.

## Decisión
**NO se mueve el código.** La reorganización es LÓGICA (documentos) y no FÍSICA (código). `runtime/` existe como concepto, no como carpeta.

## Motivo
Medición real del riesgo: **90 archivos** con imports `from app.`, **3 workflows CI congelados** (Regla de Oro 5) y 16 referencias en docs se romperían — a cambio de un beneficio puramente cosmético. La arquitectura lógica no tiene por qué coincidir con la estructura física del repositorio.

## Impacto
Cero interrupciones. Las 4 capas conceptuales quedan íntegras; el runtime vive en la raíz como en cualquier repo Python.

## Artefactos afectados
`app/` `scripts/` `data/` `.github/workflows/` (intactos)
